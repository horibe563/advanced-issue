# 要件定義書
## システム概要
このアプリは下記の機能を提供するもので、商社の社内ツールとして利用する。社内用であるため外部へのデータ受け渡しは行わない
・商品マスタの閲覧/編集
・在庫状況の確認
・入庫/出庫数の登録
・在庫数が閾値を下回っている場合は在庫状況確認画面でアラートを画面表示する
・入出庫の履歴を一覧できる（在庫状況画面の各商品にリンクを押下することで子画面で履歴情報を表示する（表示のみ））
・各データの更新には、ログインユーザのIDが設定される
・ユーザの管理は管理用画面にて行う
・ユーザ管理画面は初期表示は検索窓のみ。ID・氏名での検索が可能でユーザの登録・削除・パスワード設定が可能
・管理画面はAdminユーザのみが操作可能
・ユーザのロールは管理者と一般の2種類のみ
・各画面でアクセストークンのチェックを行う
・アクセストークンチェックでエラーとなった場合はログイン画面へ遷移する
・ログイン画面にはユーザIDとパスワードを入力する
　認証出来たらユーザのロールを確認し、トップページに遷移する（Adminロールの場合のみユーザマスタメニューを表示する）
・トークンの有効期限は一日
・トークンはブラウザのLocalstorageにて保管する
・トークンはユーザマスタに保管し有効期限を持たせる

## 入出庫伝票のルール
・伝票フラグは 1:正（加算） / 2:負（減算） の2種類のみ
・数量は常に正の整数で登録し、正負は伝票フラグで表す
・訂正時は元のレコードを上書きせず、同一伝票NOでレコードを追加する
　例）数量3・伝票フラグ1 のレコードを -1 訂正する場合、同一伝票NOで 伝票フラグ2・数量1 のレコードを追加する（実数量 = 3 - 1 = 2）
・伝票NOは数値型でアプリ側で採番する
・伝票シーケンスNOは同一伝票NO内の連番（元伝票=1、訂正ごとに+1）。伝票NO＋伝票シーケンスNOで一意
・入出庫登録時の在庫数の加減算はアプリ側で行う（DB側での自動計算は行わない）
・削除は削除フラグによる論理削除とする。更新シーケンスは楽観ロック（同時更新の検知）に使用する
