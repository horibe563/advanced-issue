
# Agent Teams 設計書

## 追加機能の概要
| 追加機能         | 概要 |
|------------------|------|
| 在庫アラート通知 | 閾値を下回った商品をまとめてリスト表示するAPIを追加する |
| CSV出力          | 在庫一覧をCSV形式でダウンロードできるエンドポイントを追加する |



## Agent構成
| Agent名 | 役割 | 担当タスク |
|---------|------|------------|
|manager-architect         |全体総括指示出し担当      |まず他のエージェントを制御する役割を担う。基本設計を担当し、各エージェントに開発を指示する。各開発・テスト状況を確認し、効率的な開発プロセスを実行できるようにする|
|backend-architect         |バックエンド担当      |追加機能のバックエンド部分だけ実装 `src/` 配下のサーバーサイドコードを担当 Express ルートと pg を使った DB 操作のパターンに従う           |
|frontend-architect         |フロントエンド担当      |追加機能のフロントエンド部分だけ実装 バックエンドの実装を待ってから実装開始  `public/` 配下のクライアントサイドコードを担当 バニラ HTML/CSS/JavaScript で実装する- fetch API でバックエンドの REST API と通信する          |
|test-architect         |テスト担当      |フロント・バックエンドの開発状況を見つつ、ある程度連携している部分が出来たらテストを実施しカバレッジ70%以上　問題なく動くかどうかのテスト結果次第で不具合あればフロント・バックエンド担当に改修を依頼し、改修後にテストを再実施する あとでテスト結果を人間が確認できるようにnpm run test:coverageで実行するテストに盛り込んでおく|
|security-architect         |セキュリティ担当      |追加機能のバックエンド部分だけ実装 フロントとバック両方の実装が管路輸したらセキュリティ観点でレビューし、発見した脆弱性についてはバックエンド・フロンドエンドの担当エージェントにタスクを遂行させる           |

## タスクの依存関係
manager Agent → backend Agent ＆ frontend → test Agent → security Agent

## 並列実行できるタスク
managerはタスクを分割し、他エージェントの生産性が発揮できるようにボトルネックにならないようにする
例えば、追加機能の１つについて設計を終えた段階で開発をエージェントに指示⇒開発中に次の要件の設計に進む
並列実行するかどうかはMangerが判断する

## 統合時の確認ポイント
Agentの出力を統合するときには、要件・設計と照らし合わせて問題ないか。開発した資産の品質が良いかどうかを判断しつつ開発結果を報告する
